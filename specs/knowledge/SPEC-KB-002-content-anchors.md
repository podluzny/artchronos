# SPEC-KB-002: Якоря на объекты базы знаний в тексте

| Поле | Значение |
|---|---|
| Блок | BL-13 |
| Requirements | FR-KB-006, FR-KB-007, FR-KB-005 |
| Scenarios | SC-KB-002 |
| Business rules | BR-048, BR-049, BR-050 |
| Domain entities | KnowledgeEntry, ContentReference, ItemVersion, TestVersion, Assignment, MediaAsset |
| Permissions | права на редактирование источника; `knowledge.read` не требуется для ссылки |
| ADR | ADR-010, ADR-002 |
| Статус | Implemented |

## Purpose
Ссылаться на объекты базы знаний из текста с поддержкой склонения, не нарушая неизменяемость утвержденного контента и санитизацию.

## Actors
Автор контента (Student, Teacher), Admin.

## Preconditions
Объекты существуют в справочниках.

## Input
| Запись | Значение |
|---|---|
| `@slug` | Ссылка; подпись — название объекта |
| `@kind:slug` | Ссылка с явным видом: person, artwork, collection, movement, period, technique, term |
| `[текст](@slug)`, `[текст](@kind:slug)` | Ссылка со своей подписью (склонение); подпись 1–200 символов без `<>[]` и переноса строки |
| `\@` | Обычный символ `@` |

`@` распознается только в начале слова: перед ним начало строки, пробел или знак препинания, кроме `.`, `_`, `\` и `@`. Поэтому `user@mail.ru` якорем не является.

Поля с якорями:
- вопрос: формулировка, текст вариантов, пояснение;
- тест: описание, инструкции;
- задание: инструкции;
- медиа: подпись;
- справочник: описание.

Не разрешены: alt text, транскрипт, названия, коды.

## Business rules
* BR-050 — канонический вид `[подпись](@kind:slug)`; студенту выводится только подпись.
* BR-049 — новый якорь на архивный объект запрещен; уже сохраненные в этом источнике якоря допустимы.
* BR-048 — slug, на который есть ссылки, не меняется.

## Main scenario
1. Автор пишет «Картина @kuindzhi и стиль [передвижников](@movement:peredvizhniki)».
2. При сохранении текст нормализуется: «Картина [Архип Куинджи](@person:kuindzhi) и стиль [передвижников](@movement:peredvizhniki)».
3. В той же транзакции источник получает строки `content_references`.
4. Предпросмотр показывает якоря как выделенный текст с подсказкой вида. Студенческое представление показывает только подписи.

## Alternative scenarios
* A1 Slug не найден → ошибка поля «Не найден объект @slug».
* A2 Slug есть в нескольких видах → ошибка «Уточните вид: @person:slug, @term:slug».
* A3 Новый якорь на архивный объект → ошибка поля.
* A4 Неизвестный вид в `@xxx:slug` → ошибка поля.

## Data changes
Текст источника (канонический вид), ContentReference.

## Authorization
Как у операции сохранения источника.

## UI behavior (AdminJS)
Подсказки к полям описывают синтаксис. Автодополнение — FR-KB-010 (F).

## Acceptance criteria
| ID | Критерий | Тип |
|---|---|---|
| AC-KB-002.1 | `@slug` нормализуется в `[Название](@kind:slug)` | positive |
| AC-KB-002.2 | `[текст](@slug)` и `@kind:slug` сохраняют подпись и вид; повторная нормализация канонического текста не меняет его | positive |
| AC-KB-002.3 | Неизвестный slug, неоднозначный slug, неизвестный вид и новый якорь на архивный объект — ошибки валидации с указанием поля | negative |
| AC-KB-002.4 | `\@`, e-mail и `@` внутри слова не считаются якорями | positive |
| AC-KB-002.5 | Рендер после санитизации дает `span.kb-ref`; представление для студента содержит только подписи | positive |
| AC-KB-002.6 | XSS-полезные нагрузки в подписи и slug не порождают разметку | negative |
| AC-KB-002.7 | Сохранение вопроса нормализует формулировку, варианты и пояснение и записывает ссылки версии; переименование объекта не меняет текст и contentHash утвержденной версии | positive |
| AC-KB-002.8 | Описание и инструкции теста, инструкции задания, подпись медиа и описание объекта справочника нормализуются и записывают ссылки | positive |
| AC-KB-002.9 | «Где используется» объекта перечисляет вопросы, тесты, задания, медиа и объекты, ссылающиеся якорями | positive |
