# ADR-002: Versioning

| Поле | Значение |
|---|---|
| Статус | Accepted (T-030, 2026-10-08) |
| Дата | 2026-10-08 |
| Задача | T-013 |
| Связанные требования | BR-002, BR-003, BR-006, BR-007, BR-010, BR-041, NFR-DATA-001, INV-001, INV-002, INV-006 |

## Контекст
Экспертиза, публикация, попытки и аналитика должны относиться к точно определенному содержимому.
Если утвержденный вопрос изменить «на месте», ранее полученные ответы и решения эксперта теряют смысл.

## Решение
**Immutable approved versions** с разделением «идентичность / версия»:

1. `Item`/`Test` — идентичность; содержимое — только в `ItemVersion`/`TestVersion`.
2. Версия замораживается при submit (content-frozen) и становится окончательно immutable при approve.
3. Любое изменение замороженной версии = новая версия (`basedOnVersionId`, `versionNo+1`), не более одного DRAFT.
4. `TestVersion` ссылается на `ItemVersion` (pinning). `Attempt` ссылается на `TestVersion`.
5. Пул случайного отбора замораживается при approve теста (`SelectionPoolEntry`).
6. Защита в трех местах: domain (инвариант), application (state guard в каждом use case), БД (триггер, запрещающий
   UPDATE/DELETE строк версий не в состоянии DRAFT и их дочерних строк, кроме полей состояния/указателей,
   изменяемых переходами).
7. `contentHash` (SHA-256 нормализованного содержимого) фиксируется при заморозке.

## Рассмотренные альтернативы
| Вариант | Плюсы | Минусы | Почему отклонен |
|---|---|---|---|
| Изменения на месте + аудит | Просто | Нельзя восстановить, что видел эксперт/студент | Нарушает BR-002 |
| Event sourcing | Полная история | Сложность для AdminJS, проекции | Избыточно для MVP |
| Снапшот JSON всего теста при публикации | Простая публикация | Дублирование, нет reuse и аналитики по вопросам | Вопросы — reusable |
| Заморозка только при approve | Автор может править «под рецензией» | Замечания относятся к меняющемуся содержимому | См. Q-007 |

## Последствия
* Число строк растет с каждой версией (приемлемо: объем текстового контента мал).
* UI должен ясно показывать «вы редактируете версию N (черновик)» и предлагать «создать новую версию».
* Нужны указатели `currentDraftVersionId`, `latestApprovedVersionId`, `publishedVersionId`.
