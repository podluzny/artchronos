# ADR-005: Хранение динамической структуры вопроса

| Поле | Значение |
|---|---|
| Статус | Proposed |
| Дата | 2026-10-08 |
| Задача | T-015 |
| Связанные требования | NFR-EXT-001, NFR-SEC-008, NFR-DATA-002, BR-020, BR-026, INV-008, INV-010 |

## Контекст
Структура вопроса зависит от типа. Нужно одновременно: расширяемость без миграций (NFR-EXT-001), ссылочная
целостность на медиа (BR-026 — «где используется»), стабильные идентификаторы вариантов для аналитики
дистракторов (INV-008), фильтрация банка по общим полям, защита ключей ответов (NFR-SEC-008).

## Решение
Граница между реляционными полями и schema-driven данными:

| Данные | Хранение | Причина |
|---|---|---|
| Идентичность, версия, состояние, тип, автор, даты, сложность, баллы, contentHash | Колонки `ItemVersion` | Фильтрация, индексы, state guards |
| Stem (формулировка) | Колонка `stem` (text, санитизированный rich text) | Поиск, общий для всех типов |
| Темы, цели, теги | Связующие таблицы | Фильтрация, целостность, BR-042 |
| Варианты/элементы (`ItemOption`) | Таблица: `key`, `role`, `text`, `mediaAssetId` (FK), `altTextOverride`, `ordinal` | FK на медиа, стабильные key, аналитика |
| Медиа-стимулы (`ItemMedia`) | Таблица с FK | BR-026 |
| Специфичные для interaction поля (shuffle, rubric, acceptedAnswers, distractor flags, параметры отображения) | JSONB `content`, валидируемый `contentSchema` | Расширяемость |
| Ключ ответа | JSONB `answerKey` (ссылается на option keys), отдельная колонка | NFR-SEC-008, отдельная сериализация |

Правила:
* Ссылки на медиа **запрещено** хранить в JSONB — только через `ItemOption`/`ItemMedia` (иначе ломается BR-026).
* Валидация: структурная (JSON Schema через Ajv) + семантическая (`plugin.validate`: например, answerKey ссылается на существующие option keys).
* Индексы GIN по `content` не создаются в MVP (фильтрация только по реляционным полям).

## Рассмотренные альтернативы
| Вариант | Почему отклонен |
|---|---|
| Весь вопрос в одном JSONB | Нет FK на медиа, нет стабильных option-сущностей для аналитики, сложная фильтрация |
| EAV (entity-attribute-value) | Сложные запросы, слабая типизация |
| Таблицы на каждый тип | Нарушает NFR-EXT-001 |

## Последствия
* Плагин описывает, какие роли `ItemOption` он использует; общий редактор вариантов переиспользуется.
* Миграции схемы БД при добавлении типов не нужны.

## Верификация
AT-QTYPE-002.2 (новый тип без миграции); AT-MEDIA-002.6 (использование медиа в варианте находится через «где используется»).
