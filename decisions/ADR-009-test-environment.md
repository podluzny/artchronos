# ADR-009: Тестовый стенд на Vercel + Neon

| Поле | Значение |
|---|---|
| Статус | Accepted (2026-10-08, решение владельца продукта) |
| Дата | 2026-10-08 |
| Задача | T-031 |
| Связанные требования | NFR-EXT-004, NFR-OBS-002; ADR-006, ADR-007, ADR-008 |

## Контекст
Нужен публичный тестовый стенд для проверки сборок без нагрузки и без реальной работы с файлами. Production-хостинг будет выбран отдельно (постоянно работающий Node-сервер, PostgreSQL, S3).

## Решение
1. **Хостинг стенда — Vercel** (проект `artchronos`). Express + AdminJS работают как одна serverless-функция (`api/index.ts`); все пути, кроме статических, переписываются на нее (`vercel.json`).
2. **БД — Neon** (интеграция Vercel). Приложение использует pooled `DATABASE_URL`; миграции применяются при сборке через `DATABASE_URL_UNPOOLED` (если есть).
3. **Фронтенд AdminJS собирается на этапе build** (`@adminjs/bundler`) в `public/admin-assets`; в рантайме сборка отключена (`ADMIN_JS_SKIP_BUNDLE=true`), AdminJS берет ассеты по `assetsCDN`.
4. **SDD-документация** остается доступна на том же стенде по пути `/sdd/`.
5. **Медиа на стенде** — драйвер-заглушка/ограничения serverless (тело запроса ≤ 4,5 МБ); производные генерируются синхронно. Это допустимо, так как стенд не используется для реальной работы с файлами.
6. **Первый администратор** создается при сборке из переменных `ADMIN_EMAIL` и `ADMIN_PASSWORD`, если в системе еще нет ни одного администратора (идемпотентно). Переменные задает владелец проекта в Vercel.
7. **Секреты**: `SESSION_SECRET` (≥ 32 символа) обязателен в окружении Vercel.

## Рассмотренные альтернативы
| Вариант | Почему отклонен для стенда |
|---|---|
| Render / Railway / Fly.io | Полноценнее, но требуют отдельного аккаунта; рассматриваются для production |
| Только локальный запуск | Нет общедоступного стенда для проверки |

## Последствия
* Холодный старт функции — несколько секунд.
* Код не зависит от Vercel: entry-point `api/index.ts` лишь адаптирует `createApp()`; production-запуск — `src/server/main.ts`.

## Верификация
Health endpoint `/health` отвечает 200 на стенде; вход администратора работает; SC-E2E-001 (по мере готовности) проходит против стенда вручную.
