## 1. Цель и границы

**Цель.** Превратить свободный текст об авторах, произведениях и музеях в справочники базы знаний. Это даст:
- выбор из справочника в формах;
- ссылки из текста через `@slug` и `[текст](@slug)`;
- «где используется» для каждого объекта.

**Входит в M7:**
- раздел «Материалы»: медиатека и 7 справочников;
- права;
- якоря в тексте вопросов, тестов, заданий, справочников и подписей медиа;
- связь медиа с произведением;
- тесты и документация.

**Не входит (F, следующие итерации):**
- автодополнение `@` в редакторе;
- поле «Объекты знания» в метаданных вопроса;
- фильтр правил отбора по объектам;
- помощник миграции старых текстовых полей медиа;
- якоря в комментариях экспертизы;
- карточка объекта для студента.

## 2. Ключевые решения (ADR-010)

| # | Решение | Отличие от аудита |
|---|---|---|
| 1 | Одна таблица `knowledge_entries` с полем `kind` (PERSON, ARTWORK, COLLECTION, MOVEMENT, PERIOD, TECHNIQUE, TERM). Видоспецифичные поля хранятся в `attrs jsonb`, связи — в `knowledge_links`. В AdminJS у каждого вида свой ресурс. | Аудит предлагал отдельные таблицы. Одна таблица дает единые поиск, slug, архив, «где используется» и проверку якорей без 7 копий кода. |
| 2 | Якорь хранится в каноническом виде `[подпись](@kind:slug)`. Подпись фиксируется при сохранении. | Аудит предлагал id в тексте и фиксацию подписи при отправке на экспертизу. Здесь подпись фиксируется сразу. Текст остается читаемым в редакторе, а contentHash не зависит от справочника. |
| 3 | Slug нельзя менять, пока на объект есть ссылки (BR-048). | Заменяет хранение id: пара `kind:slug` становится стабильным ключом. |
| 4 | Таблица `content_references` (источник → объект) пересобирается при каждом сохранении источника. Для версий вопросов и тестов источник — версия, поэтому ссылки замороженных версий сохраняются. | Как в аудите. |
| 5 | Отображение: после санитизации канонический якорь превращается в `<span class="kb-ref">`. Студенческое представление (delivery) выводит только подпись. Allow-list санитайзера не расширяется. | Проще, чем в аудите (п. 4.2.4). |
| 6 | Медиа получает `artwork_id`. При сохранении поля «Автор, Название, Датировка, Техника, Собрание, Инв. №» заполняются из произведения (BR-051). | Как в аудите. |

## 4. Definition of Done M7

- Все AC SPEC-KB-001/002 покрыты AT, тесты зеленые.
- `npm run check` и E2E проходят, axe-core — 0 нарушений.
- Миграция применяется поверх развернутой БД M6 без потери данных. Права системных ролей обновляются миграцией: seed не трогает не-ADMIN роли.
- contentHash старых версий не меняется. Якоря в старых данных отсутствуют, нормализация применяется только при сохранении.
- Документация и трассировка обновлены.

## 5. Риски

| Риск | Мера |
|---|---|
| XSS через подпись якоря | Подпись не может содержать `<`, `>`, `[`, `]`; рендер идет после санитизации; тест с полезной нагрузкой (AT-KB-002.6) |
| Ложные якоря в тексте («@» в e-mail) | `@` распознается только в начале слова; экранирование `\@`; неизвестный slug — ошибка валидации с подсказкой |
| Изменение опубликованного контента через справочник | Подпись фиксируется в тексте, slug неизменен при наличии ссылок (BR-048) |
| Подсказка ответа через ссылку | Студенту выводится только подпись, без карточки (BR-050) |
| Права у существующих ролей | Миграция добавляет права системным ролям TEACHER, STUDENT, EXPERT; пользовательские роли — на усмотрение Admin |
