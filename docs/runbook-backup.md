# Runbook: резервное копирование и восстановление

| Поле | Значение |
|---|---|
| Задача | T-084 |
| Требование | NFR-DATA-006 — RPO ≤ 24 ч, RTO ≤ 8 ч |
| Проверено | учение `scripts/backup-drill.ts`, 2026-10-08 — результат OK |

## 1. Что резервируется

| Данные | Где хранятся на тестовом стенде | Как резервируется |
|---|---|---|
| Вся предметная модель, аудит, сессии | Neon PostgreSQL | PITR Neon (история изменений) + ежедневный `pg_dump` (workflow `Backup`) |
| Файлы медиа | таблица `media_blobs` (драйвер `db`, ADR-009) | вместе с БД |
| Файлы медиа (локальная разработка) | каталог `.data/media` (драйвер `local`) | копирование каталога вместе с дампом |
| Секреты | переменные окружения Vercel | не резервируются; восстанавливаются владельцем проекта |

В production с S3 (ADR-007) нужна версионированная корзина с политикой хранения ≥ 7 дней; это часть выбора production-хостинга.

## 2. RPO ≤ 24 ч

* **Основной механизм — PITR Neon**: восстановление на любой момент в пределах окна истории проекта. Окно задается тарифом Neon; для RPO ≤ 24 ч оно должно быть не меньше 24 ч (проверьте в настройках проекта Neon → Settings → Storage / History retention).
* **Независимая копия** — workflow `.github/workflows/backup.yml`: ежедневно в 02:17 UTC шифрованный `pg_dump` в артефакт GitHub (хранение 7 дней). Включается секретами репозитория `BACKUP_DATABASE_URL` (строка подключения Neon, желательно роль только для чтения) и `BACKUP_PASSPHRASE`. Без секретов workflow ничего не делает.

## 3. Восстановление (RTO ≤ 8 ч)

### Вариант A — PITR Neon (основной, минуты)
1. Neon Console → Branches → **Create branch** from the main branch → **Point in time** = момент до инцидента.
2. Проверить данные на новой ветке (см. п. 4).
3. Переключить `DATABASE_URL` в Vercel на строку подключения новой ветки (или сделать ее основной: *Set as default*), выполнить Redeploy.

### Вариант B — из дампа
1. Скачать артефакт `artchronos-backup-<run>` и расшифровать:
   `openssl enc -d -aes-256-cbc -pbkdf2 -in backup.dump.enc -out backup.dump -pass env:BACKUP_PASSPHRASE`
2. Создать пустую БД (новая ветка/проект Neon) и восстановить:
   `pg_restore --no-owner --no-privileges --exit-on-error --dbname "$NEW_DATABASE_URL" backup.dump`
3. Проверить (п. 4), переключить `DATABASE_URL` в Vercel, Redeploy. Миграции при сборке применятся только недостающие.

## 4. Проверка восстановленной копии

`SOURCE_DATABASE_URL=… npx tsx scripts/backup-drill.ts` выполняет полный цикл на копии и проверяет:

* совпадение числа строк ключевых таблиц (пользователи, аудит, вопросы, версии, тесты, экспертизы, медиа, попытки);
* неизменность журнала аудита (число записей, максимальный id, хэш последовательности);
* целостность неизменяемого контента: `contentHash` каждой замороженной версии вопроса и теста пересчитывается из восстановленных данных (NFR-DATA-005);
* наличие байтов для каждого медиа (при драйвере `db`).

Результат учения 2026-10-08 (тестовая БД после SC-E2E-001): дамп 0,2 с / 180 КБ, восстановление 0,9 с; расхождений 0; аудит не изменен; 4 замороженные версии вопросов и 2 версии теста — хэши совпали. Время восстановления по варианту B определяется объемом; для объема тестового стенда — минуты, что укладывается в RTO 8 ч с большим запасом.

## 5. Периодичность учений
Раз в квартал и после изменений схемы хранения: запустить `scripts/backup-drill.ts` на копии (ветке Neon), приложить JSON-отчет к записи в журнале эксплуатации.
