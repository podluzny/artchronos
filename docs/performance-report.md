## Найдено и исправлено

1. **JIT PostgreSQL** добавлял ~1 с к каждому запросу списка с высокой оценкой стоимости (план выполнялся за 0,44 с, запрос — 1,5 с). JIT отключен на соединениях приложения (`SET jit = off`): для коротких OLTP-запросов он вреден.
2. **Подсчет записей списка** строился на полном запросе с соединениями справочников; теперь — только по вопросам (и отображаемой версии, если есть фильтры версии). Список преподавателя: 5,4 с → 0,68 с.

## Замечания
* NFR-PERF-003: фильтрация по scope выполняется в SQL (план запроса содержит фильтр scope до сортировки и LIMIT).
* NFR-PERF-004: превью генерируются синхронно при загрузке (принято в M3); для больших видео в production — очередь.
* На Vercel + Neon (serverless, холодные старты, удаленная БД) абсолютные значения будут выше; повторить замер на production-хостинге.
