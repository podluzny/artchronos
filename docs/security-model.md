# Security Model

| Поле | Значение |
|---|---|
| Задача | T-007, T-011, T-012 |
| Статус | Draft — ожидает review (T-030) |
| Связанные | ADR-003, ADR-006, ADR-007, permission-model.md, NFR-SEC-* |

## 1. Активы

| Актив | Угроза | Ценность |
|---|---|---|
| Ключи ответов (`answerKey`) утвержденных тестов | Утечка студентам до прохождения | Высокая — компрометирует оценивание |
| Неопубликованный контент студентов | Плагиат между студентами | Средняя |
| Учетные записи Admin | Захват → полный контроль | Критическая |
| Решения экспертизы | Подделка approve (самоутверждение) | Высокая |
| Медиа с ограниченными правами | Нарушение авторских прав | Средняя / юридическая |
| Журнал аудита | Сокрытие действий | Высокая |
| Персональные данные пользователей | Утечка | Средняя |

## 2. Нарушители

| Нарушитель | Возможности |
|---|---|
| Студент | Аутентифицирован; может вызывать HTTP-endpoints AdminJS напрямую, подменять id, параметры, состояние формы |
| Преподаватель/эксперт | То же + доступ к контенту своих курсов |
| Внешний неаутентифицированный | Доступ к странице входа и публичным endpoints |
| Скомпрометированная сессия | Действия от имени жертвы до истечения/отзыва |

## 3. Контроли

| Угроза | Контроль | Ссылки |
|---|---|---|
| Обход UI (прямой вызов action/record id) | Единый `AuthorizationService` в каждом application service; AdminJS `isAccessible` — только UI | ADR-003, ADR-004, NFR-SEC-001 |
| IDOR при чтении | Списки и `findOne` строятся через scoped repository (условие scope в SQL); недоступный объект → 404 | FR-PERM-003 |
| Самоутверждение | BR-001 в domain (author ≠ reviewer), BR-027 при назначении | INV-003 |
| Повышение привилегий | BR-015 (свои роли), запрет изменения ownerId/authorIds/state через форму (поля read-only на сервере, whitelist входных полей per action) | NFR-SEC-010 |
| Mass assignment | DTO/командные объекты с явным списком полей; AdminJS payload не передается в репозиторий напрямую | ADR-004 |
| Подбор пароля | argon2id, lockout, rate limit, одинаковые ответы для неверного email/пароля | NFR-SEC-002, NFR-SEC-005 |
| Фиксация/кража сессии | Регенерация id при входе, HttpOnly/Secure/SameSite, серверное хранилище, отзыв при блокировке и смене пароля | NFR-SEC-003, BR-014 |
| CSRF | CSRF-токен / проверка Origin для изменяющих запросов | NFR-SEC-004 |
| XSS через контент | Санитизация rich text, CSP, запрет SVG, экранирование в кастомных компонентах | NFR-SEC-007 |
| Вредоносные файлы | Проверка сигнатуры, перекодирование изображений, лимиты, отдельный домен/endpoint для выдачи, `Content-Disposition`, `X-Content-Type-Options: nosniff` | NFR-SEC-006, ADR-007 |
| Утечка ключей ответов | `answerKey` отдельно от `content`; сериализаторы по контексту; ключи видят только авторы, reviewers, admin | NFR-SEC-008 |
| Изменение утвержденного контента в обход приложения | Триггер БД, запрещающий UPDATE замороженных версий; contentHash | NFR-DATA-001, NFR-DATA-005 |
| Сокрытие действий | AuditLog append-only (права БД), запись в той же транзакции | BR-034, BR-035, NFR-AUDIT-003 |

## 4. Аутентификация и сессии

Решение — ADR-006. Параметры MVP (конфигурируемые):

| Параметр | Значение |
|---|---|
| Idle timeout | 30 минут |
| Absolute timeout | 12 часов |
| Lockout | 5 неудачных попыток / 15 минут блокировки |
| Пароль | ≥ 12 символов, не из списка частых, не совпадает с email |
| Сброс | Одноразовый токен, срок 1 час, хранится как hash |
| Смена пароля | Отзывает все прочие сессии пользователя |

## 5. Принцип «UI ≠ защита»

AdminJS-настройки `isAccessible`, `isVisible`, скрытые поля — **удобство**, не контроль доступа. Каждая операция в
application layer заново проверяет `can(...)` и BR. Это проверяется отдельным набором тестов AT-PERM-005 и
AT-PERM-MATRIX, которые не используют UI.
