# Non-Functional Requirements

| Поле | Значение |
|---|---|
| Задача | T-005 |
| Статус | Draft — ожидает review (T-030) |

Каждое NFR имеет способ верификации. Верификация выполняется в M6 (Hardening), но где возможно — автоматизируется раньше.

## NFR-SEC — Security

| ID | Требование | Верификация |
|---|---|---|
| NFR-SEC-001 | Все операции изменения и чтения ресурсов проходят server-side authorization через единый policy-сервис; UI restrictions не заменяют ее. | Тесты, вызывающие API/actions AdminJS напрямую в обход UI, для каждой ячейки permission matrix |
| NFR-SEC-002 | Пароли хранятся только как argon2id hash (параметры по OWASP); минимальная длина 12 символов, проверка по списку скомпрометированных/частых паролей. | Unit + review конфигурации |
| NFR-SEC-003 | Сессионный cookie: `HttpOnly`, `Secure` (вне dev), `SameSite=Lax`; идентификатор сессии регенерируется при входе; сессии хранятся на сервере. | Интеграционный тест |
| NFR-SEC-004 | Защита от CSRF для всех изменяющих запросов. | Интеграционный тест |
| NFR-SEC-005 | Rate limiting и временная блокировка входа: 5 неудачных попыток → блокировка на 15 минут (параметры конфигурируемы). | Интеграционный тест |
| NFR-SEC-006 | Загружаемые файлы: проверка MIME по сигнатуре (не по расширению), лимиты размера, удаление EXIF-геоданных, хранение вне web root, выдача только через авторизованный endpoint или короткоживущие signed URL. | Тесты загрузки вредоносных/поддельных файлов |
| NFR-SEC-007 | Пользовательский rich text санитизируется (allow-list) при сохранении и при выводе. | Тесты XSS-полезных нагрузок |
| NFR-SEC-008 | `answerKey` не передается в контексты, не требующие его (будущий Student Runner, списки). | Тест сериализации |
| NFR-SEC-009 | Секреты — только через переменные окружения/secret store; не в репозитории. | CI secret scanning |
| NFR-SEC-010 | Отсутствие privilege escalation: пользователь не может изменить собственные роли, scope, owner объекта, authorIds в обход правил. | Негативные тесты (M6) |
| NFR-SEC-011 | Зависимости проверяются на известные уязвимости в CI. | `npm audit`/аналог в CI |

## NFR-PERF — Performance

| ID | Требование | Верификация |
|---|---|---|
| NFR-PERF-001 | Списки ресурсов AdminJS (до 50 000 вопросов, 10 000 медиа) открываются за ≤ 1.5 с (p95) на типовом сервере. | Нагрузочный тест на seed-данных |
| NFR-PERF-002 | Сохранение черновика вопроса/теста ≤ 500 мс (p95) без учета загрузки файлов. | Нагрузочный тест |
| NFR-PERF-003 | Фильтрация по scope выполняется в запросе к БД (без загрузки всех строк в память). | Code review + тест плана запроса |
| NFR-PERF-004 | Превью изображений генерируются асинхронно; загрузка файла до 50 МБ (изображение) / 500 МБ (видео) не блокирует другие запросы. | Интеграционный тест |
| NFR-PERF-005 | Целевая одновременная нагрузка MVP: 200 активных пользователей админки. | Нагрузочный тест |

## NFR-A11Y — Accessibility

| ID | Требование | Верификация |
|---|---|---|
| NFR-A11Y-001 | Кастомные компоненты AdminJS (редакторы вопросов, review-панель) соответствуют WCAG 2.1 AA: клавиатурная навигация, фокус, подписи, контраст. | axe-core в E2E + ручной аудит |
| NFR-A11Y-002 | Alt text обязателен для изображений в вопросах (BR-025), чтобы будущий Student Runner был доступен. | AT по BR-025 |
| NFR-A11Y-003 | Модель контента позволяет хранить текстовую альтернативу/транскрипт для видео. | Review модели |

## NFR-AUDIT — Auditability

| ID | Требование | Верификация |
|---|---|---|
| NFR-AUDIT-001 | Изменение permissions, ролей и статусов пользователей журналируется. | AT |
| NFR-AUDIT-002 | Запись аудита содержит: кто, когда, что, над чем, до/после, причина (если требуется), requestId, IP. | Unit + AT |
| NFR-AUDIT-003 | Журнал неизменяем на уровне приложения и БД (роль приложения не имеет UPDATE/DELETE на таблицу). | Тест прав БД |
| NFR-AUDIT-004 | Журнал хранится не менее 5 лет; хранение пароля/хэша/токенов в журнале запрещено. | Review + тест маскирования |
| NFR-AUDIT-005 | Запись аудита пишется атомарно с изменением (BR-035). | Тест отказа записи аудита |

## NFR-DATA — Data integrity

| ID | Требование | Верификация |
|---|---|---|
| NFR-DATA-001 | Утвержденные версии assessment content являются immutable (INV-001, INV-002) — защита в domain layer и триггером/ограничением БД. | AT + тест прямого UPDATE |
| NFR-DATA-002 | Ссылочная целостность через внешние ключи; физическое удаление используемых строк запрещено (`ON DELETE RESTRICT`). | Тест миграций |
| NFR-DATA-003 | Оптимистическая блокировка (`revision`) для всех редактируемых агрегатов; конфликт → понятная ошибка, без потери данных. | Тест конкурентного редактирования |
| NFR-DATA-004 | Переходы состояний атомарны (смена состояния + указатели Test/Item + аудит в одной транзакции). | Интеграционный тест |
| NFR-DATA-005 | `contentHash` версии вычисляется при заморозке и позволяет обнаружить несанкционированное изменение. | Тест |
| NFR-DATA-006 | Резервное копирование БД и object storage, RPO ≤ 24 ч, RTO ≤ 8 ч. | Процедура восстановления, проверенная в M6 |
| NFR-DATA-007 | Даты хранятся в UTC; отображаются в часовом поясе пользователя/организации. | Unit |

## NFR-EXT — Extensibility

| ID | Требование | Верификация |
|---|---|---|
| NFR-EXT-001 | Добавление нового типа вопроса не требует изменения модели существующих типов и схемы БД. | ADR-001/005 review; тест «добавить тип-фикстуру» |
| NFR-EXT-002 | Новый interaction добавляется как плагин, реализующий контракт `InteractionPlugin` (SPEC-QTYPE-002), без изменения ядра. | Contract test для каждого плагина |
| NFR-EXT-003 | Добавление поставщика аутентификации (OIDC) не требует изменения доменной модели User. | ADR-006 review |
| NFR-EXT-004 | Замена драйвера хранилища медиа (локальный/S3) — конфигурацией. | Тест с двумя драйверами |
| NFR-EXT-005 | Модель контента пригодна для Student Runner и аналитики без миграции существующих данных (BL-12). | Review SPEC-DELIV-001 |

## NFR-MAINT — Maintainability

| ID | Требование | Верификация |
|---|---|---|
| NFR-MAINT-001 | Бизнес-правила реализованы в domain/application layer, не в AdminJS-компонентах, hooks или React (ADR-004). | Архитектурный тест зависимостей (запрет импорта domain → adminjs) |
| NFR-MAINT-002 | Строгий TypeScript (`strict`), линтер и форматтер в CI. | CI |
| NFR-MAINT-003 | Покрытие domain layer unit-тестами ≥ 90% строк; каждое BR имеет хотя бы один тест. | CI coverage + acceptance matrix |
| NFR-MAINT-004 | Каждый коммит реализации ссылается на `T-NNN`; каждый тест — на `AT-*`/`AC-*`. | Review |
| NFR-MAINT-005 | Миграции БД версионируются и применяются автоматически; откат описан. | CI |

| ID | Требование | Верификация |
|---|---|---|
| NFR-OBS-001 | Структурированные логи (JSON) с requestId, userId, без персональных данных сверх необходимого и без секретов. | Review + тест маскирования |
| NFR-OBS-002 | Health/readiness endpoints (БД, storage). | Интеграционный тест |
| NFR-OBS-003 | Метрики: время ответа, ошибки, отказы авторизации, неудачные входы, очереди генерации превью. | Review |
| NFR-OBS-004 | Отказы авторизации логируются (без раскрытия деталей пользователю). | Тест |
